# Explore a synthetic service zone

[← Back to Ahmed's profile](../README.md)

These small examples demonstrate two ways to explore engineering information directly on GitHub. All geometry, identifiers, statuses and notes are fictional.

## Rotate the geometry

Open [`service-zone.stl`](service-zone.stl) on GitHub. Drag to rotate, scroll to zoom and use the viewer's wireframe/solid controls to inspect the arrangement.

The model contains four closed rectangular solids: a structural beam, a duct, a service main and a branch. The duct sits below the beam and the smaller service route sits below the duct. The geometry is unitless and schematic, not a coordinated design or a feasibility check. STL does not carry BIM categories, materials, parameters or issue metadata.

## Search the issue register

Open [`coordination-issues.csv`](coordination-issues.csv). GitHub displays a searchable table. Search for `L03`, `Pipe` or `Reviewed` to inspect the fictional records.

The CSV demonstrates an issue register's structure. Its six records do not describe the STL model and were not exported from ClashResolveAI or BIM Engine.

## Inspect a workflow illustration

[Open the animation](../assets/coordination-study.gif) or [the static diagram](../assets/coordination-study.png).

The animation shows candidate selection, overlap review and an illustrative vertical revision. It is a code-drawn geometry study, not application footage. It does not evaluate clearance, gravity slope, constructability or a complete resolution strategy.
